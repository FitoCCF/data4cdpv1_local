## 26/10 — Pasarela PI, modelo local y extracción

### Cómo iniciar la pasarela PI
1. En Windows (máquina con AF SDK), en loopback:
   `.\gw4Pi.exe 5000 tpi.southernperu.com.pe`
2. Comprobar desde WSL: `curl http://127.0.0.1:5000/health`
3. Uso local: `pixi run python scripts/pi_tool.py buscar "<patrón>"`
4. Exposición a otras PC (opcional): `scripts/proxy_pi.py` dentro de WSL con
   `PI_TOKEN` y `ALLOW_PREFIX`. Sin `PI_TOKEN`, cualquiera que alcance el puerto
   consulta el PI con las credenciales de Windows de `gw4Pi`.

### Proxy en otro puerto
- Variable `PROXY_PORT` (por defecto 5173). Ej.: `PROXY_PORT=8989 PI_TOKEN=... pixi run python scripts/proxy_pi.py`.
- Un puerto distinto de 5173 necesita regla de firewall en Windows
  (`New-NetFirewallRule ... -LocalPort <puerto>`). En modo NAT además
  `netsh interface portproxy`; en modo `mirrored` (el de esta PC) basta el firewall.
- Clientes remotos: `PI_GATEWAY_PORT=<puerto>`.

### Modelo local
- Ollama 0.34.1 con `qwen3:14b` (~8,7 GB). El servidor se levanta con `ollama serve`.
- **Ajuste fino con datos generados por Claude:** técnicamente posible
  (datos sintéticos + QLoRA), pero los términos de Anthropic restringen usar
  sus salidas para entrenar modelos competidores: validar con legal antes.
- **Soup (trysoup.dev):** CLI Apache-2.0 de post-entrenamiento (SFT, DPO…),
  con "layer streaming" (beta) para GPU pequeñas y exportación a GGUF/Ollama.
  No genera los datos; sigue haciendo falta el dataset.
- **Model soup** (promedio de pesos/LoRA): `mergekit` o `peft.add_weighted_adapter`.
  Requiere el mismo modelo base y la misma configuración LoRA.

- Limitación detectada: la búsqueda de la pasarela es **solo por nombre de tag**,
  no por descripción. Para buscar por descripción se filtró localmente.

### Excel PSI Molienda C2 vs tabla `AssaysPsi` (`data4cdpv1/backend/works4cdp/models.py`)
- La fila 5 del Excel ya trae los nombres de campo del modelo.
- **Faltan en el Excel:** mallas 48/325/400, `P50`, distribución en micras,
  `user`, `meta_user`, `turn`.
- **Se perdería:** el P80 del PSI (columna AC); el modelo tiene un solo `P80`.
- **Semántica:** `aP*` en el Excel son *retenidos* (%m+ PSI), no pasantes como
  dice el comentario del modelo.
- **`sample`:** el Excel trae "Linea" 1/2 (números y texto mezclados); el modelo
  es FK a `Sample` → hace falta un mapeo.
- **Calidad:** horas en formatos mixtos, textos "ERROR" en P80, typos numéricos,
  valores físicamente imposibles, duplicados por fecha+hora+línea; el archivo
  llega a ago-2026 aunque su nombre dice "hasta 03-03-2026".
- **Recomendado antes de cargar:** definir mapeo Línea→Sample, decidir el P80
  del PSI, corregir el comentario de `aP*`, limpiar en la carga y usar
  `date + time + línea` como clave.

### RAG para el modelo local
- RAG no borra el conocimiento del modelo; cambia de qué fuentes responde.
- Instrucciones: `SYSTEM` en un `Modelfile` + `PARAMETER num_ctx` (≥16k).
- Texto (manuales, procedimientos) → RAG con `bge-m3`/`qwen3-embedding` + pgvector.
- Datos estructurados (PI, `AssaysPsi`) → herramientas (tool calling), no RAG.

## 28/10 — PI Web API, equipo y reporte de lamas

### PI Web API vs pasarela propia
- Ambos caminos usan AF SDK por debajo; PI Web API añade HTTPS, autenticación y
  JSON. Para extracciones masivas la pasarela debería ser igual o más rápida.
- PI Web API gana en mantenimiento, permisos por usuario y disponibilidad (no
  depende de la laptop). Recomendable para producción de `data4cdpv1`.
- La URL `/dataservers//points` está incompleta: falta el WebId
  (`GET /piwebapi/dataservers?path=\\TPI`).
- Pendiente: benchmark de ambos caminos (requiere método de autenticación y autorización).

### Equipo (Dell Precision 5820)
- Xeon W-2275 (14C/28T), 64 GB DDR4-3200 (WSL ve 31 GB por defecto),
  Quadro RTX 5000 16 GB (Turing, sin bf16), WSL2 en modo `mirrored`.

### Reporte del Espesador de Lamas (`Reporte_Espesador_de_Lamas_PI.xlsm`)
- **Estructura:** `MParametros Operacion` (oculta) calcula con PI DataLink
  (`PIAdvCalcVal`) el promedio horario ponderado por tiempo de ~42 tags para
  12 h; la fila 27 es el promedio del turno. La macro `Workbook_Open` pega
  valores en `Parametros Operacion`, `REPORTE` (H13:H36) y `Consolidado`.
- **Turno:** después de las 15:00 reporta el turno A del día (06:00–18:00);
  antes, el turno B del día anterior (18:00–06:00).
- **Regeneración sin PI DataLink:** summary `TimeWeighted` de 1 h vía
  `pi_client`, fechas congeladas, cálculo con Excel por COM y pegado como
  valores. Salida fuera del repo (`~/reportes_lamas/`).
- **Hallazgos en el libro original:**
  - Nombres definidos XLM rotos (`_xleta.AVERAGE`, `_xleta.TIME`) que impiden
    guardar como `.xlsx`; se eliminan.
  - Kilos de floculante (columna BH) es un valor fijo, no viene del PI.
  - "Nivel de poza pulmón promedio" es en realidad la última hora.
  - H1 del REPORTE muestra la fecha como número serial.
  - El encabezado dice 06:30–18:30 pero se promedian 06:00–18:00.
